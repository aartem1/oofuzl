# Метрика `comment_noise`

Слой `comments` в `measure.py`: находит комментарии, не несущие информации сверх кода рядом,
и отдаёт их аудиту как долг, который выжигает `fix`.

## Задача

Агенты оставляют в коде комментарии, пересказывающие соседнюю строку. Они занимают контекст
следующего агента и не сообщают ему ничего.

Позиция, из которой сделан дизайн: код должен читаться без комментариев; если без комментария
код непонятен — чинить надо код.

## Почему не плотность комментариев

Плотность (`comment_lines / total_lines`) как метрика качества не подтверждена:

- Arafati & Riehle, ICSE 2009, 5229 OSS-проектов: корреляция с размером проекта −0.008,
  с размером команды −0.055.
- Aman: закомментированные модули в 1.8–3.5 раза чаще дефектные. Комментируют сложное,
  метрика меряет сложность.
- Fluri, WCRE 2007: 97% правок комментариев идут в одной ревизии с правкой кода. Плотность —
  почти константа проекта.
- Steidl, ICPC 2013: копирайты составляют 18–49% объёма комментариев. Pascarella, MSR 2017:
  59% строк комментариев не относятся к читаемости кода.
- Steidl измерил Goodhart на ConQAT: обязательное правило «у члена класса должен быть
  комментарий» породило 1774 тривиальных комментария.

«Оптимальный диапазон 30–60%», циркулирующий в блогах, не возводится ни к одному первоисточнику.

## Метрика

```
noise_comment_lines   строки комментариев, классифицированных как шум
```

Растёт при ухудшении. `config.level_for` сравнивает `value >= threshold` и ратчет guard'а
сравнивает `value >= max(baseline + 1, warn)` — обе работают без правки.

Порог абсолютный, не долевой: 40 мусорных строк стоят агенту одинаково в файле на 200 строк
и в файле на 3000.

Файл без комментариев даёт 0 и не порождает находок. Метрика односторонняя: давления
«добавь комментарий» нет нигде.

Единица значения — строки. `evidence` несёт оценку токенов по формуле `ceil(chars / 4)`,
той же, что у `file_tokens`.

## Классы шума

### Считаются в значение

**`commented_out`** — закомментированный код. Алгоритм `eradicate`:

1. whitelist директив и task-тегов;
2. отсев `#[0-9]` (ссылка на issue) и `# -*- coding: … -*-`;
3. обязательный индикатор кода: `( ) [ ] { } : = %` или `print|return|break|continue|import`;
4. многострочные случаи: строка кончается на `\`, `^\s*\w+\s*=.*[(\[{]$`, строка из скобок;
5. `compile(line, '<string>', 'exec')` — парсится как Python ⇒ код.

Измеренная точность: P 0.89 / R 0.95 (Steidl 2013), F1 0.80 (Oztas 2025).

**`trivial_doc`** — комментарий, пересказывающий имя сущности под ним. Coherence coefficient
(Steidl 2013):

1. нормализация: снять разделители комментария, теги, спецсимволы;
2. слова комментария = split по пробелам;
3. слова идентификатора = split имени по camelCase и snake_case;
4. слова совпадают ⟺ расстояние Левенштейна < 2;
5. `c_coeff = |совпавших| / |всех слов комментария|`;
6. `c_coeff > 0.5` ⇒ шум.

Пример из статьи: `/** removes all defined markers */` над `removeAllMarkers()` даёт 0.75.
Корректность ~90%, валидирована опросом 16 разработчиков на 30 примерах, согласие >80%
в 9 случаях из 10.

Производственный аналог — правило `informative-docs` в `eslint-plugin-jsdoc`: то же вычитание
токенов имени из слов описания, порог бинарный вместо 0.5.

### Только в `evidence`, не в значение

**`short_inline`** — inline-комментарий из ≤2 слов после нормализации. 70% разработчиков
в валидации Steidl удалили бы такой либо вынесли бы его текст в имя функции.

Не входит в значение, потому что 0.70 ниже, чем 0.89 и 0.90 у первых двух: сумма трёх классов
имела бы точность слабейшего. Подсчёт бесплатен, а `fix` уже открыл файл.

### Иммунитет

Один regex-проход до порогов, без обращения к другим слоям. Комментарий не классифицируется
как шум, если срабатывает любое из правил:

| Правило | Проверка |
|---|---|
| Длина | ≥30 слов после нормализации |
| Причина | `because\|workaround\|otherwise\|hack\|иначе\|потому что\|поэтому` |
| Ссылка на issue | `#\d+`, `[A-Z]{2,}-\d+`, URL |
| Единицы и системы отсчёта | `ms\|sec\|bytes\|utc\|epoch\|0-based\|1-based\|px\|hz` |
| Границы диапазона | `inclusive\|exclusive\|включительно` |
| Пустое значение | `null\|None\|nil\|undefined\|empty` |
| Владение и время жизни | `caller must\|owns\|frees\|closes\|releases\|освобожда` |
| Лицензия | `copyright\|licen[sc]e\|SPDX` |
| Директива инструмента | `noqa\|type:\s*ignore\|eslint-disable\|pylint\|pyright\|nosec\|fmt:\|isort:\|NOSONAR\|go:generate` |
| Task-тег | `TODO\|FIXME\|XXX\|HACK` |
| Служебное | shebang, `# -*- coding: … -*-` |

Steidl и Pascarella независимо показали, что эти категории составляют до 59% строк комментариев.
Без иммунитета метрика меряет лицензии.

Правило «упоминает сущность из другого модуля» (Ousterhout, cross-module comments) в v1 не
реализуется: оно требует таблицы символов из слоя `imports`, то есть зависимости между слоями
ради одного правила иммунитета. Правила «≥30 слов» и «причина» покрывают большинство таких
комментариев.

## Чего детектор не ловит

| Комментарий | Класс |
|---|---|
| `# print(old_result)` | `commented_out`, ~0.89 |
| `/** removes all markers */` над `removeAllMarkers()` | `trivial_doc`, ~0.90 |
| `// increment counter` над `counter += 1` | пограничный, c_coeff = 0.5 |
| `// loop through items` над `for item in items:` | **не ловится** |

Последняя строка требует entailment-скоринга языковой моделью (Louis et al., 2018, CRAIC).
В v1 её нет, и отчёт обязан это писать — как уже пишет про nesting для Ruby и dead code для JS/TS.

## Языки

| Язык | Извлечение комментариев | Классы |
|---|---|---|
| Python | `tokenize.COMMENT` + `ast` для docstring и деклараций | все три |
| brace-языки | сканер `//`, `/* */` с учётом строковых литералов | `trivial_doc`, `short_inline` |
| остальное | — | `None`, не ноль |

`commented_out` вне Python требует своего парсера-верификатора; до его появления класс
`not_measured`, а слой `partial` с названной причиной. Прецедент — `symbol_collision`
и `dead_symbol`, оба Python-only.

Список поддержанных brace-языков верифицируется тем же flat-vs-deep пробником, каким
верифицировали nesting lizard'а (`references/tools.md:52-70`).

## Находка

Числа в примере иллюстративные — пороги назначаются позже, см. «Пороги».

```json
{
  "id": "comment_noise:backend/reports.py",
  "kind": "comment_noise",
  "layer": "L2",
  "level": "warn",
  "subject": {"file": "backend/reports.py"},
  "metric": "noise_comment_lines",
  "value": 34,
  "threshold": 20,
  "evidence": {
    "tokens": 410,
    "commented_out": {"lines": [88, 89, 90], "count": 3},
    "trivial_doc": {"lines": [12, 45, 203], "count": 3},
    "short_inline": {"lines": [7, 19, 22], "count": 3},
    "immune": 14
  }
}
```

Одна находка на файл, а не на комментарий: иначе на репозитории с тысячей мусорных
комментариев `findings` станет нечитаемым, а единица работы `fix` — всё равно файл.

Группировка — по подсистеме/каталогу, как у `file_too_long`.

Потолок приоритета — **P2**, по прецеденту `dead_symbol` (`references/quality-policy.md:145-148`):
точность 0.8–0.9 это повод посмотреть, а не доказательство.

## Комментарий как симптом плохого кода

`c_coeff = 0` означает, по Steidl, либо «комментарий не несёт информации», либо «имя плохое»
(8 из 10 в опросе). Отдельной находки такой комментарий не порождает.

Если он стоит на функции, которая уже светится в `function_too_complex` или `too_deep_nesting`,
его id попадает в `finding_ids` этой группы как evidence. Паттерн re-ranker'а: так уже устроены
`hotspot` и `edit_fanout` (`references/metrics.md:98-101`).

Группу из одних re-ranking находок создавать нельзя (`references/ledger.md:79-95`).

## Защита от «снести все комментарии»

Существующие пять anti-gaming правил (`skills/fix/SKILL.md:187-201`) вырезание комментариев
не ловят: тесты целы, конфиги не тронуты, файлы не удалены. Правило 5 сравнивает repo-wide
`summary`, а он при удалении комментариев **улучшается** по `file_lines` и `file_tokens` —
то есть подтверждает ложное улучшение.

Шестое правило: удалённые в диффе строки комментариев сверяются со списком строк из
`evidence` находки. Удалено то, чего в списке нет ⇒ reject, item `failed`, цикл стоп.

Сравнение двух множеств номеров строк. Токенов агента не тратит.

## Корпус

`tests/fixtures/comments.py` — строки вида `(текст, контекст, ожидаемый класс)`.
Раннер `tests/test_comments.py` прогоняет корпус и печатает precision по классам.

Корпус обязателен не ради покрытия: без измеренной точности метрику по правилам репозитория
публиковать нельзя, она попадает под `not_measured` (`references/tools.md:83-86`).

Обязательные кейсы — те, на которых ломается `ruff ERA001` (открытые баги трекера):
PEP 723 inline script metadata, правильно оформленный TODO, слово `return` в прозе,
пример кода внутри комментария, директива `# ruff: ignore[…]`, `#` внутри строкового литерала.

Целевая точность: ≥0.85 для классов, входящих в значение. Класс ниже порога уходит
в `evidence` — тем же решением, каким туда попал `short_inline`.

## Пороги

Не назначаются на этом этапе. Снимаются с 3–5 живых репозиториев после того, как корпус
покажет точность — как снимали `parameters.hard = 8` (воспроизвести известные 114 функций)
и `near_duplicate.min_similarity = 0.60` (поймать наблюдённые 64–75% обёртки).

## Вне области v1

- **guard.** Метрика попадает в ратчет отдельным заходом, после калибровки порогов.
  Там своя работа: у существующих `baseline.json` нового ключа нет, `base_values.get(key)`
  вернёт `None`, потолок схлопнется в `warn`, и файлы начнут падать без единой правки кода.
  Нужна либо трактовка «ключа нет ⇒ не проверяем» по образцу `nesting: None`, либо
  подъём `schema` baseline'а.
- **Entailment-скоринг языковой моделью.** Закрывает `// loop through items`, стоит запуска
  модели на каждый комментарий. Противоречит требованию «максимум статикой».
- **Метрика бесполезности тестов.** Единственный работающий ответ — mutation testing,
  десятки минут CPU на прогон.
- **Счётчик документированности** (публичные функции без комментария). Это mandated-comment
  механизм, породивший 1774 тривиальных комментария в ConQAT.
- **Исключение комментариев из `file_tokens`.** Комментарии реально стоят модели токенов;
  метрика меряет стоимость чтения файла честно. Ложное «улучшение» от вырезания комментариев
  закрывает шестое anti-gaming правило, а не изменение формулы.
