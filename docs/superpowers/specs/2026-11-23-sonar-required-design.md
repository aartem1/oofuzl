# Sonar — обязательное предусловие аудита, рейтинги, на которые можно опираться

Дата: 2026-11-23. Версия плагина: 0.7.0.

## Зачем

Аудит 23.11 прошёл без Sonar, потому что Docker не был запущен: надёжность, безопасность,
покрытие и сопровождаемость вышли «не измерено», P0 не мог появиться в принципе. Пользователь:
«Без работающего сонара это все бессмысленно». Второе требование: рейтинги Sonar должны
показывать реальную картину — аудит объясняет каждую букву и предлагает, как её честно поднять.

## Решения

1. **Sonar — предусловие, а не слой.** Новый скрипт `scripts/sonar_ready.py` до любых замеров:
   - нет `docker` в PATH — стоп, одна строка с тем, что установить; сам ничего не ставит;
   - `docker info` не отвечает — на macOS `open -a Docker` и ожидание с пределом (по умолчанию
     180 с); на другой ОС — стоп с командой запуска;
   - контейнер SonarQube: здоровый переиспользуется, остановленный запускается, иначе создаётся
     `sonarqube:community` с именованными томами `sonarqube_data|extensions|logs`; ожидание
     `/api/system/status = UP` с пределом (по умолчанию 300 с);
   - токен: `SONAR_TOKEN`, иначе файл `~/.config/code-health/sonar-token`, иначе старый
     `~/.config/sonar-code-health/token`; проверяется `/api/authentication/validate`. Нет
     действующего — на свежем сервере (`admin:admin`) пароль меняется на случайный, выпускается
     токен, оба пишутся в `~/.config/code-health/` с правами 600; иначе пробуется сохранённый
     пароль администратора; иначе стоп.
   - Вывод — JSON без секретов (`host`, `container`, `token_file`, `version`, `actions`). Сбой —
     код 1, причина и одна команда исправления по-русски.
   Запуск Docker и создание контейнера больше не спрашиваются отдельно: это и есть приказ
   «требовать сонар и настраивать его как надо».
2. **Любой сбой Sonar останавливает аудит.** Нет частичного отчёта, нет «не измерено» в строках
   Sonar. 403 на профиле качества — тоже стоп с названием нужного права. Убрана таблица «что
   теряется без L1» и оговорка про невозможный P0.
3. **Покрытие подаётся в Sonar,** если в репозитории есть команда покрытия: она запускается с
   отчётом вне репозитория. Нет такой команды — строка «Покрытие» говорит именно это.
4. **Рейтинги объясняются.** Новый скрипт `scripts/sonar_ratings.py` читает меры и задачи
   проекта и для надёжности, безопасности, сопровождаемости, проверки уязвимых мест, покрытия и
   дублирования выдаёт: текущую букву или процент, задачи, которые её задают (худшая
   серьёзность), и что нужно для следующей буквы. Правила букв — правила SonarQube (MQR):
   надёжность и безопасность — по худшей серьёзности открытой задачи; сопровождаемость — по доле
   техдолга (≤5 % A, ≤10 B, ≤20 C, ≤50 D); проверка уязвимых мест — по доле проверенных
   (≥80 % A, ≥70 B, ≥50 C, ≥30 D).
5. **Каждая задача, задающая букву, разбирается:** настоящая — пункт исправления; ложная —
   архитектурно верное исправление причины (поменять шаблон кода, на который срабатывает правило;
   правило или профиль с записанной причиной в Sonar-конфигурации репозитория; правильная
   настройка сканера — исходники, тесты, генерированный код, пути отчёта покрытия). Без подгонки:
   никакого массового `NOSONAR`, удаления тестов, отключения правил без причины, исключения
   настоящего кода. Аудит сам ничего не меняет — решение уходит в группу журнала.
6. **Приоритет.** Группы, поднимающие рейтинг, идут первыми в «Что чинить первым» с ожидаемой
   буквой после исправления. В группе журнала — поле `rating`: `{metric, from, to}`.
7. **fix для группы с `rating`** после изменения прогоняет анализ Sonar на ветке (предусловие —
   тот же `sonar_ready.py`) и сообщает рейтинг до и после; буква не сдвинулась, как ожидалось, —
   это сказано прямо.

## Что не меняется

Аудит только читает целевой репозиторий; токен не попадает в чат, команды и вывод; Docker и
другие среды выполнения не устанавливаются.

## Проверка

Юнит-тесты обоих скриптов на подменённых `docker`/HTTP; полный набор тестов плагина; реальный
аудит `~/Documents/jira-team-analytics` с поднятием Sonar и объяснением текущей буквы E по
надёжности.
