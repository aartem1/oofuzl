# Изменения

## 0.6.0

Исправления по ревью 13.11.

Аудит (`measure.py`):

- Вложенность считается только для Python: у lizard счётчик вложенности переходил из файла в файл, и TS/JS-функции получали чужую глубину.
- Слой мёртвого кода снова выдаёт находки: vulture 2.16 сообщает о них кодом 3, а плагин считал его сбоем. Версии vulture, jscpd и madge закреплены.
- Разобранный объект в параметрах JS/TS (`({ a, b, c }) =>`) считается одним параметром.
- Одноимённые методы разных классов и вложенные функции различаются по полному имени (`Job.run`, `outer.inner`); идентификатор находки больше не содержит номер строки.
- Функция и вложенная в неё функция не считаются дублем.
- Тесты TSX/JSX, `__tests__`, `.yarn`, `coverage` и `*.min.js` не считаются исходным кодом.
- Точные клоны ищутся только между файлами кода, и `--files` сужает их; временная папка jscpd удаляется.
- Граф импортов JS/TS больше не обрывается на 64 КБ.
- Размер файлов `.vue`, `.svelte`, `.sql`, `.sh` измеряется (только строки и токены).
- `--brief N` — сжатая сводка: статусы слоёв, число находок по видам и N худших каждого вида.
- `--history FILE` — одна строка на аудит, чтобы видеть, как меняется код.

Проверка перед коммитом (`guard.py`):

- Папка `.code-health/` никогда не проверяется: первый коммит после установки больше не падает на самом `guard.py`.
- Коммит, который поднимает потолки через `baseline.json` или `config.json` (поднятый эталон, ослабленный порог, новое исключение, удалённый эталон), отклоняется. Подсказки про `--no-verify` в тексте отказа больше нет.
- `--base REF` — та же проверка на сервере сборки для всех изменений ветки относительно `REF`.
- `update-baseline` не записывает эталон, который поднимает потолки, без `--accept-worse`.
- Новые строки, отключающие линтер (`noqa`, `type: ignore`, `eslint-disable`, `@ts-ignore` и подобные), считаются по правилу «не больше, чем было».
- Файл, перенесённый `git mv`, сохраняет эталон старого пути.
- Сбой lizard выводится предупреждением, а не проходит молча.

Навыки: `fix` напоминает запустить `update-baseline` после улучшения и может работать в git worktree — журнал долга общий для всего репозитория.

Как обновиться в репозитории с установленной проверкой: заново скопировать `scripts/guard.py` в `.code-health/guard.py`, добавить `vue, svelte, sql, shell, json` в `types_or` хука и запустить `update-baseline`. Старый эталон читается и без этого. Если в репозитории есть большие файлы `.vue`, `.svelte`, `.sql` или `.sh`, они впервые попадут в эталон выше порога, и `update-baseline` попросит `--accept-worse`; такой коммит делает человек.
